# tp7ls: language server для Turbo Pascal 7 — порт на Free Pascal

Цель: перенести рабочий прототип на Python (`python/`, см. `python/CLAUDE.md`) на Free Pascal 3.2.2 (`/usr/bin/fpc`,
x86_64-linux). Прототип остаётся **эталонной реализацией**: если порт и прототип расходятся, прав прототип, пока
владелец не решит иначе. Всё из разделов «Зафиксированные решения» и «Правила работы» в `python/CLAUDE.md` действует
и для порта (только TP7, cp866 + CRLF, жёстко зафиксированное форматирование, никаких ложных срабатываний,
никаких угаданных фактов о TPU).

## Язык
- Документация (`.md`) и сообщения коммитов — на русском. Коммиты немногословные: одна строка, при необходимости
  пара строк пояснения.
- Сообщения сервера (диагностики и т. п.) — на английском, как в прототипе.
- Комментарии в коде — по минимуму, в идеале без них: код должен быть понятен сам. Комментарий только там, где
  без него не понять почему (например, проверенный факт о формате TPU).

## Устройство
- `src/` порт. `src/tp7ls.lpr` точка входа; модули называются по модулям Python
  (`tp7lex.py` -> `src/tp7lex.pas`, `tpu_dump.py` -> `src/tpudump.pas`, ...). `src/tp7enc.pas` перекодировка
  cp866 <-> UTF-8, чтение файлов, пробелы / `strip` / `upper` / `lower` / `repr` с семантикой Python. Программы командной строки —
  `src/*cli.lpr`, собираются в `build/` без `cli` (`src/tp7lexcli.lpr` -> `build/tp7lex`).
- `src/tpudump.pas`: словари `tdesc` прототипа — класс `TTypeDesc` с полем `Kind` (`tdNamed`, `tdArray`, ...);
  `None` у строковых полей — пустая строка (прототип пустых строк там не даёт), у чисел — `-1`, у списков — флаг
  `Has...`. Всем владеет `TLoader`. `IndexError` / `struct.error` прототипа — `ETpuIndex` / `ETpuStruct`: где
  прототип ловит только одно из них, порт тоже. Вещественные константы: `'%.15g'` Python — свой точный `FormatG15`
  (`FloatToStrF` в FPC округляет неверно), мантисса `Extended` округляется до 53 бит вручную (`QWord -> Double`
  в FPC тоже неточен).
- Токены (`TToken`) и узлы (`TNode`) — классы: на один токен ссылаются дерево, `Sig`, `Leading`, `Via`, как в Python.
  Всем владеет `TParseResult` (узлы — в его списке, не в родителе), освобождается только он. Дети узла — `TKids`
  (`array of TObject`: `TNode` или `TToken`). Голый `Lex` отдаёт токены вызывающему: `FreeTokens`.
- `src/tp7sema.pas` (+ `tp7index`, `tp7maps` — упорядоченные словари строка / указатель -> объект, как `dict`,
  `tp7os` — `os.path` в семантике Python). Замыкания прототипа (`tfn`, `fields_fn`, `own_fn`, `ancestor_fn`,
  `target_fn`, `elem_fn`) — данные в `TSym` (`TfKind` + контекст) и `TTInfo` (`Members`, `HerName`, `PtrName`,
  `ElemNode` / `Desc`), вычисляются лениво методами `GetFields` / `GetOwn` / `GetAncestor` / `GetTarget` / `Elem`.
  `BROKEN` прототипа (IndexError и пр. на сломанном дереве): обращения через `Kid` / `KN` / `KT` бросают `EBroken`,
  ловится там же, где в прототипе. Владение: всё, что создаёт `TBinder`, — в его арене; всё, что создаёт
  `TProvider` (модули, их разборы и биндеры, TPU, типы из TPU), — в арене провайдера; `TURBO.TPL` — общий кеш на
  процесс. Binder освобождать раньше своего Provider. `Binder` на `unit` без имени падает (как в прототипе) —
  сервер должен ловить исключения анализа, как ловит прототип.
- `src/tp7types.pas`: `Ty` прототипа — `TTy`; все `TTy` / `TSpec` принадлежат своему `TTypes` (кроме встроенных:
  `IntegerTy`, `StringTy`, ... и `FloatTy`), поэтому `int_const` / `common_int` — методы `TTypes`. `None` у чисел
  `lo` / `hi` / `value` / `maxlen` / `strlit` — флаги `Has...`. `TypeError` Python при сравнении числа с `None`
  (`lo <= v <= hi` у поддиапазона без верхней границы) — `EBroken` в `OutOfRange`; где прототип его не ловит
  (`Checker`), проверка файла прерывается, как в прототипе. `ExprAt` отдаёт `TExprAt` (свой `TTypes`, токены, тип) —
  освобождает вызывающий. Модуль теста нельзя называть `ttypes`: совпадает с `TTypes`.
- Рекурсивный вызов функции внутри неё самой писать со скобками (`TypeSpec()`): без них FPC читает имя функции
  как её результат.
- `for S in ['a', 'bcd']` в FPC 3.2.2 молча обрезает строки до длины первого литерала (тип выводится как короткая
  строка). Так нельзя: `for S in Strs([...])` (`tests/tutil.pas`) или типизированная константа-массив. Открытые
  массивы-параметры (`Kw(['begin', 'end'])`) этим не страдают.
- Порядок вычисления операндов и аргументов в FPC не определён: если в выражении несколько вызовов с побочным
  эффектом (`Tx` отмечает токен выведенным), разбивать на последовательные присваивания.
- `tests/` FPCUnit: раннер `tests/tp7tests.lpr`, по модулю на каждый набор Python (`test_tp7lex.py` -> `tests/tlex.pas`).
  Образцы для тестов: `python/samples` и папка `TP7LS_DATA` (`make test` передаёт `testdata`; имена файлов — без
  учёта регистра, `DataFile`); тест, которому нужен отсутствующий файл, помечается ignored (с `testdata` таких нет).
  Тесты сверх наборов Python допустимы, если закрывают дыру в спецификации.
- `tools/compare.py` сверка: запускает прототип и командную строку порта на одних и тех же файлах и сравнивает
  (`lex`: дамп токенов; `parse [-D SYM]`: дерево, диагностики, неактивные токены, `{$I}`, восстановление текста;
  `fmt [-D SYM] [--width N]`: вывод форматтера побайтно, stderr и код возврата; `tpu [--lib TPL]`: `--json` как
  данные, `--pas` и `--names` побайтно; форматы — в docstring скрипта). Программы `build/tp7lex`, `build/tp7parse`,
  `build/tp7fmt` (`-w N` — ширина, 0 — без переноса, `--normalize --path --tpl`), `build/tpudump`, `build/tp7sema`
  (`--dump`); `sema [--path] [--tpl]`: на что ссылается каждое имя, объявления, неразрешённые / неуверенные имена,
  ненайденные модули, повторы, нормализованный текст; `types [--path] [--tpl]` (`build/tp7types --dump`): ошибки
  типов, inlay-подсказки, типы имён, тип выражения у каждого оператора / скобки / `^`.
- `python/` прототип; при переносе в папку не менялся (кроме `CLAUDE.md`). Его тесты запускаются из любого каталога.
- `build/` результаты сборки (git их игнорирует).

## Сборка и тесты
- `testdata/` — образцы владельца для тестов (TURBO.TPL, GRAPH.TPU, POLSK.PAS/.TPU, polsk.pas, option.pas, оба
  `*_formatted.pas`, TEST.PAS/.TPU, WINXP.PAS/.TPU). OBJECTS.TPU / VIEWS.TPU / SAMPLES*.TPU лежат в `python/samples`
  и в `testdata` класть нельзя: `test_tp7sema.test_samples` ждёт, что модуля `objects` рядом с TEST.PAS нет.
- `make` собирает `build/tp7ls`; `make test` собирает и запускает тесты FPCUnit (при ошибке код возврата != 0);
  `make pytest` — все наборы прототипа (оба на `testdata`, другая папка — `DATA=папка`). Должны проходить все.
- `make compare FILES="testdata python/samples"` запускает `tools/compare.py` для лексера, парсера и форматтера.
- Папки `../intrfc70` и `../fpc-*` не трогать вовсе (не читать, не использовать для проверок). Для сверки с
  прототипом на большом объёме кода годятся `../BP`, `../robot`, `../vdisk` (только читать).
- Утечки: собрать с `heaptrc` (`fpc -O- -gl -gh ...`, в FPC нет `-O0`) и запустить тесты — должно быть
  `0 unfreed memory blocks`.
- Ключи компилятора — в `Makefile` (`-Mobjfpc -Sh`, проверки диапазона / переполнения / ввода-вывода, assert'ы);
  каждый модуль к тому же начинается с `{$mode objfpc}{$H+}`, чтобы собираться и без `Makefile`.
- Git: глобальный `~/.config/git/ignore` скрывает все файлы на точку, новые такие файлы добавлять через `git add -f`.
  Исходники Turbo Pascal (тестовые данные, сейчас `python/samples/`) в рабочем дереве в cp866 с CRLF, в git —
  в UTF-8 с LF (`.gitattributes`: `working-tree-encoding=CP866`, `eol=crlf`). Новую папку с такими файлами
  добавить в `.gitattributes`. Исходники порта (`src/`, `tests/`) — обычные, UTF-8 с LF.

## Порядок порта
1. Лексер (`tp7lex`) — сделано. Один лексер, написанный вручную; `lex_reference` прототипа не переносится (это
   эталон для его ускоренного варианта на регулярках). `compare.py lex` чисто на всех исходниках этой машины
   (`testdata`, `python/samples`, `../robot`, `../vdisk`, `../BP`) и на случайных входах.
2. Парсер (`tp7parse`, вместе с `prepare`: IFDEF, `{$I}`) — сделано. Перенесены `test_tp7parse.py` и класс
   `Splice` из `test_tp7inc.py` (класс `Includes` — протокольный, переносится с сервером). `compare.py parse` чисто
   на тех же исходниках, на случайных входах (с `-D A` и без) и на испорченных настоящих программах.
   Намеренное отличие: глубина вложенности ограничена счётчиком (`MaxNesting`), а не стеком Python, поэтому
   «nesting too deep» у порта наступает позже (~500 скобок против ~200).
3. Форматтер (`tp7fmt`) — сделано, без `normalize` (нужен `tp7sema`; тест на это помечен ignored). Перенесён
   `test_tp7fmt.py` (`tests/tfmt.pas`). `compare.py fmt` чисто на всех исходниках этой машины, на программах со
   случайными пробелами / переводами строк / комментариями / директивами, с `-D` и на ширинах 0, 20, 40, 50, 70, 120.
4. `tpu_dump` -> `tpudump` — сделано. Перенесён `test_tpu_dump.py` (`tests/ttpu.pas`, регулярные выражения через
   `RegExpr`). `compare.py tpu` чисто на всех TPU/TPL из `testdata`, `../BP`, `../robot`, `../vdisk`, `python/samples`,
   с `--lib TURBO.TPL` и без; `FormatG15` / `RealText` сверены с Python на 65 000 / 32 000 случайных значений.
5. `tp7sema` и `tp7index` — сделано, нормализация в форматтере включена. Перенесены `test_tp7sema.py`
   (`tests/tsema.pas`) и класс `Tree` из `test_tp7index.py` (`tests/tindex.pas`; `Workspace` — протокольный).
   `compare.py sema` и `fmt --normalize` чисто на всех исходниках (с TPU Turbo Vision из `../BP/UNITS` и без) и на
   4200 сломанных / случайных программах.
6. `tp7types` — сделано. Перенесены классы `Rules`, `Results`, `Files` из `test_tp7types.py`
   (`tests/ttyperules.pas`; `Server`, `Inlay` — протокольные). `compare.py types` чисто на всех исходниках
   (с TPU Turbo Vision и без) и на сломанных / случайных программах.
7. Затем `tp7stub` и сервер (`tp7lsp`; JSON через fcl-json).

## Строки и кодировки (решение владельца)
- Текст исходников внутри порта — UTF-8 (`AnsiString`/`UTF8String`), как приходит от редактора. Файлы с диска
  при чтении перекодируются cp866 -> UTF-8 своей таблицей (без `cwstring`/iconv); перекодировка без потерь,
  обратно в cp866 — той же таблицей. Другая однобайтовая кодировка — другая таблица.
- Лексер работает по байтам: всё значимое в TP7 — ASCII, байт >= 0x80 бывает только в строках и комментариях.
  Регистр идентификаторов — только ASCII.
- Смещения внутри — в байтах. Где нужны символы, считать символы:
  1. позиции LSP: `positionEncoding: utf-8`, если клиент согласен; иначе пересчёт в UTF-16 (только для строк
     с не-ASCII);
  2. ширина строки в форматтере (120) и предел TP7 (126, `TP_LINE_LIMIT`) — в символах (= байтах cp866);
  3. длина и значение строковых литералов в проверке типов (`'Ж'` — `Char`) — через cp866;
  4. имена и строки из TPU/TPL — cp866, перекодировать при чтении; заглушки писать на диск в cp866;
  5. колонка в дампе токенов для `compare.py` — в символах, как в прототипе.

## Правила работы
- Переносить поведение, а не только код: для каждого перенесённого модуля переносится его набор тестов Python
  и `compare.py` проходит чисто.
- Не тащить идиомы Python там, где в Pascal есть простой способ (записи / классы, `TFPGList` или массивы), но
  сохранять алгоритмы и имена прототипа, чтобы обе версии читались рядом.
- Не менять прототип под порт; если в прототипе ошибка — сказать владельцу и исправить в обоих.
